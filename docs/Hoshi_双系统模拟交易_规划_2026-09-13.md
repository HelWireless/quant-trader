# hoshi-cplus 双系统模拟交易 —— 规划（待确认）

> 目标：模拟 **2020-01-20 → 2026-09-01** 的完整交易过程，初始资金 **30 万**。
> 关键设计：**策略系统与交易执行系统彻底分离**，执行侧带 20% 概率的操作偏差，
> 用来量化"信号对、执行烂"到底吃掉多少收益。
> 本文件是规划，确认后再动手实现。

## 一、核心约束（不可违背）

| # | 约束 | 实现方式 |
|---|---|---|
| 1 | 策略系统**只能用目标日之前的数据** | 计算 T 日信号时，只查 `sig_by_date[T-1]` |
| 2 | 交易系统用**当日数据**判断能否成交 | 只接收 T 日 OHLC |
| 3 | **两个系统必须分离** | 各自独立类，**不 import 对方内部状态**，只通过委托/回报通信 |
| 4 | 同一套日线输入 | 两边读同一份 `hoshi_csv_2005` |
| 5 | 可复现 | 偏差用固定随机种子 |

```
                     ┌──────────────────────────────┐
                     │   同一套日线数据 (CSV)        │
                     └──────────────┬───────────────┘
                    T-1 及以前 │              │ T 当日 OHLC
                              ▼              ▼
   ┌────────────────────────────┐    ┌────────────────────────────┐
   │  系统 A · 策略引擎          │    │  系统 B · 模拟撮合          │
   │  (strategy_sys)            │    │  (broker_sim)              │
   │                            │    │                            │
   │  · 查 T-1 信号             │    │  · 接委托                  │
   │  · 广度门控                │    │  · 按 T 日 OHLC 撮合       │
   │  · 结合持仓/现金 生成委托   │    │  · 施加 20% 概率的偏差     │
   │  · 生成当日出场条件         │    │  · 回报成交结果 + 行情     │
   └─────────────┬──────────────┘    └─────────────┬──────────────┘
                 │                                  │
                 │      OrderRequest[]  ──────────► │
                 │                                  │
                 │  ◄──────────  FillReport[] + 行情快照
                 │                                  │
   ┌─────────────▼──────────────┐                   │
   │  持仓账本（A 独立维护）     │                   │
   │  现金 / 成本 / 股数 / 峰值  │                   │
   └────────────────────────────┘                   │
                 ▲                                  │
                 └──────────────────────────────────┘
                        驱动层 runner 逐日串起
```

**要点**：A 永远看不到 T 日的价格（除了 B 在回报里给的行情快照），
B 永远不知道策略逻辑。两者只认协议。

## 三、通信协议（两系统唯一接口）

**A → B：委托**

```json
{
  "date": "2020-01-20",
  "kind": "BUY",              // BUY | SELL
  "code": "301111",
  "shares": 1700,
  "reason": "score=9.0",
  "trigger": null             // SELL 时给：触发价（止损价 / 止盈回落价）
}
```

**B → A：回报**

```json
{
  "date": "2020-01-20",
  "code": "301111",
  "kind": "BUY",
  "status": "FILLED",         // FILLED | MISSED | REJECTED
  "fill_price": 27.42,
  "shares": 1700,
  "fee": 7.13,
  "deviation": "SLIP_UP",     // 见第五节偏差标签
  "market": {                 // 当日行情快照，供 A 更新峰值/账面
    "open": 27.95, "high": 28.60, "low": 27.10, "close": 28.20
  }
}
```

## 四、系统 A（策略）每日流程

时间点：T 日**盘前**，只拿得到 T-1 及以前的数据。

1. **买入候选**：查 `sig_by_date[T-1]`，筛 `score ≥ 9.0`
2. **广度门控**：用 T-1 的广度值，`< 20%` 则当日不开新仓
3. **仓位计算**：`权益 × 10% ÷ 参考价`，向下取整 100 股；
   权益 = 现金 + 持仓成本（**与回测口径一致**）
4. **出场条件**：对每个持仓，按持有天数生成当日要执行的触发价
   - 第 5 天起：`止损价 = 成本 × 0.94`
   - 第 14 天起：若峰值 ≥ `成本 × 1.052` → 改为 `峰值 × 0.988` 的移动止盈
   - 第 25 天：标记"开盘价卖出"
   - 第 40 天：兜底
5. **输出委托**：买入委托 + 出场委托（**A 不发"卖出"，只发"触发条件"**）

> A 完全不知道 T 日会不会成交、成交在什么价 —— 那是 B 的事。

## 五、系统 B（撮合）与偏差模型

时间点：T 日**收盘后**结算，用 T 日 OHLC 撮合。

### 5.1 基准成交价

| 委托类型 | 基准价 |
|---|---|
| 买入 | T 日 `open`（与回测口径一致） |
| 止损卖出 | A 给的 `trigger` 价（若当日 `low ≤ trigger` 才算触发） |
| 移动止盈 | `peak × (1 − 1.2%)` 与 `open`/`high` 的关系决定 |
| 超时卖出 | T 日 `open` |

### 5.2 偏差模型（总异常概率 20%）

**买入委托**

| 标签 | 概率 | 行为 |
|---|---:|---|
| `OK` | 80% | 以 `open` 成交 |
| `SLIP_UP` | 8% | 追高：成交价 = `min(open × (1+u), high)`，`u ~ U(0.3%, 2%)` |
| `LUCKY_LOW` | 4% | 侥幸：成交价 = 当日 `low` |
| `MISSED` | 8% | **买入失败**，当日不成交（次日**不补单**，模拟真实漏单） |

**卖出委托**

| 标签 | 概率 | 行为 |
|---|---:|---|
| `OK` | 80% | 以触发价成交 |
| `SLIP_DOWN` | 8% | 割肉：成交价 = `max(trigger × (1−u), low)`，`u ~ U(0.3%, 2%)` |
| `LUCKY_HIGH` | 3% | 侥幸：成交价 = 当日 `high` |
| `MISSED` | 9% | **当天没卖出去** → 次日 A 会再次生成同样的出场条件（相当于延后一天重试） |

> 用户原话"20% 左右也不是一直有问题" → 每笔委托独立掷骰，不是全局状态。

### 5.3 不建模的部分（先说明，避免高估真实性）

- **涨跌停一字板**：暂不特别处理（`MISSED` 已近似覆盖"买不进/卖不出"）
- 流动性冲击、成交量约束
- 分红送转（数据是不复权价，长持会有偏差）

## 六、每日时序

```
T 日 盘前    A 运行 → 产出 OrderRequest[]
                  ↓
T 日 收盘后  B 运行 → 用 T 日 OHLC 撮合（含偏差）→ 产出 FillReport[]
                  ↓
             A 消费回报 → 更新现金/持仓/峰值 → 记净值曲线
                  ↓
T+1 日 盘前  循环
```

## 七、输出物

| 文件 | 内容 |
|---|---|
| `sim_trades.csv` | 逐笔成交：日期、代码、方向、委托价、成交价、偏差标签、股数、费用、盈亏 |
| `sim_equity.csv` | 每日净值：日期、现金、持仓市值、总权益 |
| `sim_signals.csv` | 每日信号与门控状态（A 侧日志） |
| `sim_report.md` | 汇总报告 |

**汇总报告要包含**

1. 最终资金、总收益率、年化、最大回撤
2. 交易笔数、胜率、平均单笔
3. **偏差统计**：各标签发生次数与占比
4. **🔑 对照实验**：同一策略跑两遍 —— **有偏差 vs 无偏差（理想执行）**，
   直接给出"执行偏差一共吃掉多少收益"
5. 与同期回测基准的对比

> 第 4 点是这次模拟最值钱的产出：它把"执行损耗"变成一个具体数字。

## 十、验收标准

实现完成后必须通过：

1. **无偏差版的结果应与回测引擎一致**（同一策略同一区间，误差 < 0.1pp）
   —— 这是证明"两系统拼接没写错"的锚点
2. **有偏差版只应比无偏差版差**，不应出现"偏差反而赚更多"的异常
3. `sim_trades.csv` 与 `sim_equity.csv` 的资金流必须自洽（现金 + 持仓成本 = 初始资金 ± 盈亏）
4. A 侧日志显示的委托，与 B 侧回报必须一一对应（不丢单、不重复）
