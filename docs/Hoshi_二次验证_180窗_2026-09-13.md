# 二次验证：双盲重建 + 180 窗 × 3 方案

> 目标：排除"结论依赖特定实现"的风险。做法是**只依据报告的规格文字**重建一套回测引擎，
> 再用**更大的样本**（数据从 2005 年起、180 个随机窗口）验证三个方案的排序是否稳定。
> 生成时间：2026-09-13

## 一、双盲重建

### 1.1 做法

- 先依据 `docs/Hoshi_终局报告_2026-09-13.md` §3 的规格**独立实现** `scripts/hoshi_rebuild_v2.py`，
  实现过程中不参考 `hoshi_backtest_exp5.py`。
- 然后用**原数据** `hoshi_csv_long` 跑 3 个已知锚点窗口，与原引擎对拍。

### 1.2 对拍结果（方案 B：9分 / 启用日5 / −8.2% / R3关）

| 窗口 | 原引擎锚点 | 重建引擎 | 差异 |
|---|---:|---:|---:|
| 2011-03-01 ~ 2016-02-29 | +153.1699% / 380笔 | **+153.17% / 380笔** | **0.00** |
| 2014-12-01 ~ 2016-11-30 | +146.8178% / 197笔 | **+146.82% / 197笔** | **0.00** |
| 2020-10-01 ~ 2022-09-30 | +52.7429% / 376笔 | **+52.74% / 376笔** | **0.00** |

**收益与笔数逐位一致** → 报告 §3 的规格自洽，可脱离原实现重建。

### 1.3 重建过程中发现并修正的 3 个问题

| # | 问题 | 影响 |
|---|---|---|
| 1 | 报告规格漏写：广度参与样本需"该标的至少 66 根 K 线"（只写了 ≥60） | 广度分母不一致 → 已补进报告 §3.2 |
| 2 | 重建代码 bug：广度数组用"个股 bar 索引"累加，回测时按"全局日期索引"取值 | 停牌会导致错位 → 已改为按 `didx[date]` 累加 |
| 3 | 重建代码 bug：漏了"买入当天推进一次 `hold_day`" | 武装/止损/超时/强平**全部晚一天**，收益差 −25% → 已补 |

第 3 点正是双盲重建的价值：它是原引擎的一个**非显然行为**（买入当天即计为 `hold_day=1`），
报告里虽写了"买入当天推进为 1"，但如果实现时忽略，结果会系统性偏差。

## 四、结论

1. **报告规格可独立重建**：3 个锚点零误差对拍通过。
2. **B′ 是最优方案，且在更大样本上优势更强**：
   - 60 窗主实验：B′ − B = **+15.45pp**（51胜60）
   - **180 窗二次验证：B′ − B = +24.39pp（160胜179，p=5.8e-29）**
   - 样本扩大到 2005 年起点后，效应量不减反增。
3. **尾部也最好**：最差窗 −6.78%（B −8.11%、原版 −33.53%），负窗 4/179（B 13、原版 68）。
4. **一致性极强**：8 个持有期档、14 个起点年份，B′ **全部**胜出。
5. **实盘动作不变**：关闭 R3，止损保持 **−6.0%** 不动。
