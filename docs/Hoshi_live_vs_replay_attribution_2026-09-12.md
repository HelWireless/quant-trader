**不是策略不同，是口径不同。**

| 我 H5S9 / 方案 B 复盘 | 295,330.24 | **−1.56%** |

→ **策略层面只差 0.19pp。他的 −5.68% 里有 3.93pp 是记账问题，不是策略亏的。**

## 2. 五个真实差异，逐个拆

### ① 参数版本不同（最大头）

| 时间 | 他的 MIN_SCORE |
|---|---|
| 09-07 22:53 之前 | **8.0** |
| 09-07 22:53 之后 | 9.0 |

**华钰矿业是 8.0 分的信号**（9-03 出的）。我全程 9.0 分门槛 → **根本不会买它**。
这一笔是他亏损的主要来源：9-04 起算，若持有到 9-11 收盘 21.16，−10.7%。

### ② 他是人工下单，仓位与策略给的完全不同

| | 股数 | 金额 | 占权益 |
|---|---|---|---|
| 策略给（原版，10% 上限） | 1,200 | 28,435 | **10%** |
| 他实际买 | **4,000** | 88,214 | **29%** |

他自己也标注了「用户自主决定」。**同一笔信号，仓位差 3.3 倍 → 亏损放大 3.3 倍。**
这不是策略差异，是执行差异。

### ③ 现金口径被人为改过（−3.93pp）

他附录 C 自己算的：
```
09-07 13:48 买华钰后现金应为 300,000 - 88,214.05 = 211,786
09-07 22:53 被直接置为 200,000   ← 11,786 元无任何交易解释
```
`11,786 / 300,000 = 3.93pp`。**这就是 −5.68% 与 −1.75% 的差额来源。**
→ 建议：拿真实券商账户现金校准一次 `hoshi_live_state.cash`。

### ④ 9-01 / 9-02 他还在「K线缓存静默截断」故障期

他的文档第 4 节：缓存 bug 导致 **5014 只里 3552 只只有 26 根 K 线，真实选股池只剩 1445 只**，
近 30 日信号数从 36 掉到 4。**这个 bug 是 09-03 才发现并修的。**

所以他的 9-01、9-02 两次「无信号」是**漏报**，不是真空仓。
我这边 9-02 有 1 个 9 分信号：**603758 秦安股份 @ 12.03**（他没买，因为看不见）。
→ 秦安我 9-09 硬止损 −8.29% 卖出，这一笔他有、我没有。

### ⑤ 止损参数不是同一个维度

| | 他的（hard5_score9_p6） | 我的（H5S9 / B） |
|---|---|---|
| 硬止损启用日 | 第 5 天 | 第 5 天 |
| 硬止损阈值 | **−6.0%**（p6，9-08 改） | 引擎默认（−8.2%） |

他调的是**阈值**，我调的是**启用日**。两者可叠加，**组合效果从未验证过**。
他的 p6 是 42 格网格 + 21 个随机窗口选出来的；我的"止损5"是 60 窗双组验证的。
**不要默认两者等价。**

## 3. 唯一没能解释的差异（需他在 WSL 上查）

他的 9-07 20:00 扫描只出了 **4 只**；我的同参数扫描出 **7 只**：

| 300642 | 透景生命 | 8.5 | ✅ | ✅ |
| 600613 | 神奇制药 | 8.5 | ✅ | ✅ |

| **002086** | **东方海洋** | 8.0 | ❌ | ✅ |

排除的可能性：
- ❌ **不是 ST 过滤** —— 腾讯自选股查得 3 只现名分别是「金正大」「百花医药」「东方海洋」，均无 ST 前缀。
- ❌ **不是数据错** —— 三只的 OHLC 已与独立源逐位核对一致。

最可能：**这 3 只不在他的选股池 / `daily_kline` 数据不完整**。
他 9-03 修复后自报「可扫描 4997/5014」，**仍有 17 只不可扫描**；且 TDX 主源从 9-09 起连续 3 天 0 命中、靠 BaoStock 兜底。

**排查清单（在 WSL 上跑）：**
```bash

  "select code,count(*) from daily_kline where code in ('002470','600721','002086') group by code;"
# 期望：每只 >= 250 根；若某只缺失或 < 65 根 → 缓存/补数问题

  "select code,name,list_date from stock_info where code in ('002470','600721','002086');"
```

## 4. 一个反直觉的发现：这 9 天看不出 B 比 H5S9 好

```
H5S9(9分/止损5/R3开)   期末 295,330.24   -1.56%   买3 卖1 持仓2
方案B(9分/止损5/R3关)  期末 295,330.24   -1.56%   买3 卖1 持仓2   ← 完全相同
```

**R3 在这 9 天里一次都没触发**，所以 B 与 H5S9 结果逐位相同。
R3 的差异要在长窗口才显现（60 窗：B 比原版 **+68.17pp**，比 T5 **+21.62pp**）。

→ **不要拿这 9 天的实盘去评判 R3 该不该关。** 需要至少跑满几个完整窗口。

## 5. 建议（按优先级）

1. **校准现金**：把 `hoshi_live_state.cash` 改成真实券商账户现金，清掉那 11,786 的黑洞。
2. **补查 3 只漏选股**（见第 3 节 SQL）—— 这可能是他系统里一个真实的、正在持续发生的漏信号 bug，比这 9 天的盈亏重要得多。
3. **明确"系统 vs 人工"边界**：华钰 4000 股（29% 仓位）是人工决策。若要看策略真实表现，应单独记一条"人工干预"标记，别混进策略评价。
4. **别混用两套参数**：他现在的 `hard5_score9_p6`（阈值 −6.0%）和我的方案 B（关 R3）是**不同维度**的改动。要合，得先做一次组合验证（用 `hoshi_fixrun.py` 跑 60 窗），别直接叠。
5. **9-01/9-02 的漏报要回溯**：缓存修复后应重跑 9-01~9-02，确认秦安股份确实是漏报而非判据不同。
