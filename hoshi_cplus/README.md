# hoshi-cplus

A 股**超跌反弹**策略，是 Hoshi 策略经 2026-09 一轮系统研究后的优化版本。

---

| 历史称呼 | 现名 |
|---|---|
| 方案 B′（B prime） | **hoshi-cplus** |
| 方案 B | 方案 B（保留原名，作为对照基线） |
| 原版 | 原版（保留原名，作为对照基线） |

> 自 **2026-09-13** 起统一命名为 **hoshi-cplus**。两者**完全等价**，代码里

**hoshi-cplus = 评分 9.0 + 硬止损第 5 天起武装 + 硬止损 −6.0% + 关闭 R3 + 广度门控 20%**

---

## 一、它是什么

一句话：**在大盘仍处于多头排列的个股中，找"连跌两天 + 企稳 + 次日收阳"的买点，
用早武装的硬止损控制回撤，靠高周转与复利累积收益。**

核心逻辑：
1. 只买 **MA20 > MA60** 的票（趋势未破）
2. 要求**连续两天**跌幅 < −2%（跌得急）
3. 第三天出现**企稳**K 线（锤子线 / 十字星 / 小实体）
4. 第四天**收阳**确认
5. 按"跌得深不深 + 企稳质量 + 确认日强度"打分，只做高分票
6. 第 5 天起就武装 **−6.0%** 硬止损，跌破无条件走人

## 二、验证结论（截至 2026-09-13）

| 对比 | 效应量 | 显著性 |
|---|---:|---|
| hoshi-cplus vs 方案 B（仅止损阈值不同） | **+24.39pp**（160胜179，89%） | t=11.83，p=5.8e-29 |
| hoshi-cplus vs 原版 | +109.58pp（173胜179，97%） | t=15.25，p=1.1e-43 |

**180 窗总览**（数据 2005 起，5310 只，179 个有效随机窗口）：

| 方案 | 几何收益 | 中位 | 最差窗 | 负收益窗 |
|---|---:|---:|---:|---:|
| 原版 | +15.82% | +20.37% | −33.53% | 68/179 |
| 方案 B | +89.19% | +109.40% | −8.11% | 13/179 |
| **hoshi-cplus** | **+109.07%** | **+136.69%** | **−6.78%** | **4/179** |

- 优势**随持有期单调放大**：1年 +1.5pp → 7年 +46pp
- **14 个起点年份全部胜出**（14/14）
- 样本从 60 窗扩大到 180 窗后，效应量**不减反增**（+15.45pp → +24.39pp）

## 四、快速开始

```python
from hoshi_cplus import Strategy

# 首次会加载 + 预计算（几千只标的约 1~5 分钟），之后可在同一进程内反复跑窗口
s = Strategy('scripts/hoshi_csv_2005', preset='cplus')

r = s.run('2011-03-01', '2016-02-29')
print(r['ret'])        # 收益率 %
print(r['n_trades'])   # 完成交易笔数
print(r['final_capital'])
```

命令行：

```bash
# 单窗口
python -m hoshi_cplus --data scripts/hoshi_csv_2005 --preset cplus \
    --start 2011-03-01 --end 2016-02-29

# 批量：多方案 × 多窗口
python -m hoshi_cplus --data scripts/hoshi_csv_2005 \
    --windows scripts/windows_180.csv \
    --schemes cplus,B,original --out verify.csv
```

## 五、数据要求

目录模式，每个 CSV 一个标的：

```
date,open,high,low,close,volume
2004-01-02,8.51,8.65,8.41,8.64,5804700
```

- 文件名 `<6位代码>_<名称>.csv`（名称可省略）
- **不复权原始价格**
- 标的池建议用白名单过滤：`sh600/601/603/605/688/689` + `sz000/001/002/003/300/301`，
  并剔除 ST / 退市 / 上市首日 N 股
  （库里混着指数、ETF、债券、国债逆回购，它们的"价格"不是股价）
- 现成数据：`scripts/hoshi_csv_2005/`（2004-01-02 起，5310 只）

## 七、实现时的三个坑（改代码前务必读）

这三个细节漏掉任何一个，结果都会系统性偏差，而且**看起来像是"参数不对"**：

1. **买入当天就要推进一次 `hold_day`**（`COUNT_ENTRY_DAY=True`）。
   漏掉会让武装 / 硬止损 / 超时 / 兜底强平**全部晚一天**，实测收益差 **−25%**。
2. **广度的样本条件**：该标的需**至少 66 根 K 线**（不只是"截止昨天 ≥60 根"）。
3. **广度按全局日期索引累加**，不能用个股 bar 索引 —— 停牌会让两者错位。

## 八、实盘下单（信号 → 委托）

```bash
# 扫描某日的买入信号，输出可直接照做的指令单
python -m hoshi_cplus --data scripts/hoshi_csv_2005 --scan 2026-06-18
# 扫描最近 N 个交易日
python -m hoshi_cplus --data scripts/hoshi_csv_2005 --scan-last 20
```

**买入方式**：回测口径是「信号日**次日开盘价**」买入。
实盘在次日 9:15–9:25 集合竞价挂**市价单**，或挂略高的限价单
（如信号日收盘 ×1.02）确保成交。注意 **T+1**，买入当天不可卖。

**条件单时间表（关键）**：券商条件单**只支持价格触发，不支持时间条件**，
而本策略有「第 5 天起武装硬止损」「第 25 天超时」这类**时间规则** ——
所以必须按指令单生成的时间表**手动挂 / 改 / 撤**：

| 时点 | 动作 |
|---|---|
| **D1 开盘** | 买入（次日开盘） |
| D2–D4 | 无止损保护（策略设计：前 4 天裸奔，是 −6.0% 口径的一部分） |
| **D5 开盘前** | ★ 挂条件止损单：现价 ≤ 买入价 × 0.94 卖出全部（−6.0%） |
| D14 收盘后 | 若期间最高价 ≥ 买入价 × 1.052 → 撤止损单，改挂**移动止盈**（自最高价回落 1.2% 卖出） |
| D15 | 若仍未触发止盈，止损单继续有效 |
| **D25 开盘** | ★ 撤销全部条件单，**市价卖出**（超时平仓） |
| D40 | 兜底强平（正常走不到） |

**实盘与回测的已知差异**：回测的「反弹卖出」规则（第 15 天起，跌破 −5.2% 后
反弹 +2.2% 卖出）在多数券商条件单里**做不出来**，实盘建议只用 −6.0% 硬止损覆盖。
两者行为接近但不等价 —— 改动前建议先量化这个差异。

## 九、已知限制

- **未建模滑点**。回测已扣佣金、印花税、过户费，但策略交易的是超跌小盘股，
  冲击成本不低，实盘收益会低于回测。
- **无幸存者偏差处理**：标的池按"当前名称表"剔除 ST/退市，历史上已退市的票未纳入。
- 出场用当日 OHLC 判定（跌破即按触发价成交），实盘可能有偏差。
