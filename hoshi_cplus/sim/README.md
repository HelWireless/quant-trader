# hoshi_cplus / sim —— 邮件驱动纸面交易模拟

**目标**：用 hoshi-cplus 策略 + QQ 邮件里的「Hoshi实盘」每日指导，做一次 **30 万本金、1 个月**的
前瞻性纸面交易，验证是否盈利。

---

## ⚠️ 必读：邮件清单 ≠ 本地复算（其他 agent 最常见的困惑）

**症状**：其他 agent 拿到的「服务器邮件买入清单」，和用本仓库 `hoshi_cplus` 代码本地复算的结果**对不上**。

**结论**：**两边是同一套 hoshi-cplus 逻辑，不是两个策略。** 不一致是因为**服务器那份邮件当天扫描不全**。

**实证（确认日 2026-09-17 → 买入 2026-09-18）**：

| 代码 | 名称 | 9-17 涨幅 | MA20 | MA60 | MA20>MA60 | 本地 detect_signal | 服务器邮件 |
|---|---|---:|---:|---:|:--:|---:|:--:|
| 300970 | 华绿生物 | +4.32% | 19.192 | 18.071 | ✓ | 9.5 | ✓ |
| 000011 | 深物业A | +6.44% | 8.697 | 7.791 | ✓ | 9.0 | **✗ 漏** |
| 300061 | 旗天科技 | +7.91% | 6.500 | 6.468 | ✓ | 9.0 | ✓ |
| 600108 | 亚盛集团 | +6.82% | 4.133 | 3.419 | ✓ | 9.0 | **✗ 漏** |
| 600822 | 上海物贸 | +9.96% | 8.688 | 8.300 | ✓ | 9.0 | ✓（**确认日涨停**） |

- 本地复算命中 **5 只**，逐只复核**全部合规**（连跌两日 + 企稳 + 确认收阳 + MA20>MA60）。
- 邮件只列 **3 只**：漏掉 000011 / 600108，却把确认日**涨停**（开盘买不进）的 600822 列了进来。
- 可能原因：①服务器当日**数据缺口**（其历史邮件多次出现「数据不全 / 覆盖率 0/0」告警）；
  ②**涨停口径不稳**（09-14 剔除涨停的 605168，09-17 又保留涨停的 600822）；③两家实现细节差异。

**本项目采用的规则（推荐对齐）**：
1. **双源交叉核对**：邮件 + 本地 `scripts/hoshi_scan_live.py` 都跑；
2. **不一致时以本地扫描为准**（同代码、可复现、更完整）；
3. **剔除「确认日涨停」的票**（涨幅 ≈ +10%/+20% 且 收=最高）——开盘买不进；
4. 汇报里**必须列出两源差异**。

> 🕳️ **工程坑**：本环境有两个 mail 连接器——**qq-mail**（`mcp__qq-mail__*`）与 **agent-mail**（`mcp__agent-mail__*`）。
> 读 Hoshi 邮件**必须用 qq-mail**；误用 agent-mail 会返回 `not_bound`、表现为"读不到邮件"。
> 本模拟的自动化曾连续 4 天误用 agent-mail，导致一直没读到邮件、只能用本地扫描兜底。

📄 完整说明与决策记录见 **`docs/Hoshi_邮件纸面模拟_说明与决策_2026-09-17.md`**。

## 组件

| 文件 | 作用 |
|---|---|
| `mail_trader.py` | 引擎：读 duckdb 行情、按信号买入、跑 step_exit 出场、逐日 mark-to-market 落台账 |
| `state.json` | 账户状态（现金 / 持仓 / 待买入 / 历史） |
| `ledger.csv` | 逐日权益台账（date, cash, mkt_value, equity, ret_vs_start, n_pos） |
| `trades.csv` | 成交流水（date, side, code, name, price, shares, amount, reason） |
| `resync.py` | **与真实成交对账**：把持仓/成本改写成实盘实际成交，重算现金与台账 |
| `reconcile.csv` | 对账审计流水（每次 resync 追加一行） |
| `scan_YYYY-MM-DD.json` | 该确认日的 live 扫描原始结果（候选 + 广度） |
| `_backup_pre_resync/` | 最近一次对账前的三件套快照（可回滚） |

## 两种口径：策略模拟 vs 实盘镜像

- **策略模拟**（原始设计）：pending 里的信号全部按规则成交，用来验证策略本身。
- **实盘镜像**（2026-09-16 起启用）：真实账户因为资金/情绪/挂单等原因没买或买在别的价位时，
  用 `resync.py` 把模拟改成**实际成交**，这样后续的每日建议才和真实持仓对得上。
  镜像会污染"策略纯收益"的结论 —— 要评估策略本身请另跑回测，别用本账户。

```bash
# 与真实成交对账（只修正指定日期的买入，其它日期流水原样重放）
python hoshi_cplus/sim/resync.py --day 2026-09-15 \
    --positions "002365:永安药业:1900:14.302,300901:中胤时尚:1500:18.593" \
    --note "300736 未成交；按实盘成本价修正"

# 当日有卖出时必须用 --sells 显式登记（--positions 只表达"对账后仍持有的仓位"）
python hoshi_cplus/sim/resync.py --day 2026-09-21 \
    --positions "002365:永安药业:1900:14.302:2026-09-15,..." \
    --sells "300647:超频三:8.14:3500,300901:中胤时尚:17.71:1500" \
    --cash 95013.71 --mode S4 --note "09-21 早盘卖出对账"

# live 信号扫描（用最新一根收盘当确认日，执行日 = 下一交易日）
python scripts/hoshi_scan_live.py --data scripts/hoshi_csv_2005 \
    --held 002365,300901 --equity 298545.93 --json hoshi_cplus/sim/scan_2026-09-16.json
```

> **`resync.py` 是幂等的**：同日重跑会用 `--positions/--sells` **完全重建**该日的持仓、流水与台账行。
> 因此标准做法是 **盘中先对一次账（拿到实盘成交）→ 收盘后再跑同一条命令把该日刷成收盘口径**。
> 重跑会清空 `pending`，所以要在 `set-pending` **之前**跑。


## 规则

- **本金** 300,000 元（起始 2026-09-15）；**单只仓位** = 上一日权益 × 10%；最多同时 10 只。
- **买入**：信号日次日**开盘价**成交；**涨停开盘买不进**（主板 +10% / 创业板·科创板 +20%）→ 跳过；
  股数 = `floor(预算 / 开盘价 / 100) × 100`；含手续费（万 2.5、最低 5 元、卖出印花税千 0.5、沪市过户费）。
- **出场**（hoshi-cplus，复用 `hoshi_cplus/exits.py:step_exit`）：
  T+1 不可卖 → D5 起 −6.0% 硬止损 → D14/D15 武装止盈(峰值回落 1.2%/1.0%) →
  D15 起反弹式止损 → D25 超时开盘平 → D40 兜底强平。
- **信号源**：QQ 邮件「Hoshi实盘 YYYY-MM-DD」（发件人 2587225803@qq.com，在 `sent` 文件夹）。

## 用法

```bash
python hoshi_cplus/sim/mail_trader.py init --capital 300000 --start 2026-09-15
python hoshi_cplus/sim/mail_trader.py set-pending --for 2026-09-15 "002365:永安药业,300901:中胤时尚,300736:百邦科技"
python hoshi_cplus/sim/mail_trader.py run 2026-09-15      # 处理该交易日起的所有缺口日
python hoshi_cplus/sim/mail_trader.py capital --rebase    # 重置基准=当前资金池权益（剔除未投入本策略的资金）
python hoshi_cplus/sim/mail_trader.py capital --add 10000 # 追加资金 1 万（现金与基准同增，不影响既有收益率）
python hoshi_cplus/sim/report.py                        # 汇总结果 → report.md + trades_paired.csv
python hoshi_cplus/sim/mail_trader.py status
```

> **资金池语义**：本模拟追踪的是「投入 hoshi-cplus 的那部分资金」。真实账户里被**非本策略标的**占用的钱
> 不计入——用 `capital --rebase` 把基准重置为当前资金池，之后通过 `capital --add` 追加资金。
> 与真实成交对账用 `resync.py`（支持 `--cash` 指定可用现金、`--mode S3|S4` 指定出场模式）。

> 跑之前确保 `data/tdx.duckdb` 已刷新到目标交易日（`scripts/refresh_tdx_duckdb.py` + 清 9998 脏行）。
